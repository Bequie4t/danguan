# 첫 개발 단위 검증 결과 (2026-10-08)

대상: 공통 기록 구조 + 웹 실제 저장 (Next.js + Supabase, https://danguan.vercel.app)
원칙: 실제로 실행한 것만 "확인"으로 쓴다. 코드로만 구현했거나 다른 환경에서만 확인한 것은 따로 적는다. 모든 시험은 가상 사용자·가상 내용만 썼다.

## 검증 수준 구분
- **실DB**: 실제 Supabase 프로젝트 `danguan`에서 가상 사용자 A/B를 만들어 SQL로 실행. 실행 끝에 일부러 오류를 내서 전부 되돌렸다(남는 데이터 없음).
- **로컬DB**: 이 작업 공간의 임시 PostgreSQL 16 + Supabase 흉내 환경에서 실행(36개 항목).
- **단위**: 화면 상태 로직(formState)과 저장 로직(api) 단위 시험(9개, tsx --test).
- **화면 E2E**: 실제 사이트에서 브라우저로 로그인해 눌러 본 시험.

## 실DB 실행 기록
- 1차(2026-10-07): 12개 항목 통과. 동의 없이 저장 거부, A 생성, 재전송 1행, 수정 v2, 옛 버전 수정 충돌, B 조회·수정·ID 가로채기·A 이름 생성·직접 수정 거부, 비로그인 조회 0행, 비로그인 저장 거부.
- 2차(2026-10-08, 지우기 함수·비로그인 차단 적용 후): 7개 항목 통과. B 삭제(함수·직접) 거부, 옛 버전 삭제 충돌·기록 유지, A 삭제 성공, 비로그인 조회 거부(42501), 비로그인 삭제 함수 거부(42501).
- Supabase 보안 점검: 표·RLS 관련 지적 0건. 남은 경고 1건 "유출된 비밀번호 차단 꺼짐"(인증 설정, 출시 전 켜기).

## 남은 위험
- 화면 E2E(⬜)는 로그인한 브라우저에서 실행해야 한다. 계정 생성·비밀번호 입력은 사용자가 직접 해야 해서 아직 하지 못했다.
- 시험 편의를 위해 Supabase "Confirm email"을 꺼 두었다. 실제 사용자를 받기 전에 다시 켜야 한다.
