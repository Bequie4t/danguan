## 2. 남아 있던 문제와 수정

### 2.1 이전 화면의 콜백이 새 계정으로 요청하는 문제

예: A 화면이 살아 있는 동안 인증 이벤트가 공유 guard를 B로 바꾼다. 화면 정리 전에 A 저장 콜백이 실행되면 이전 구현은 호출 순간의 B 표를 새로 발급한다. 따라서 A 입력이 B의 세션 확인을 통과할 수 있다.

`AuthScope`의 화면 렌더에 UID·generation을 묶고, `useScopedRequest`가 그 값을 캡처한다. `guardedRequest`는 이 표를 필수로 받는다. 오래된 화면의 표는 세션 조회 전에 거부한다. A→로그아웃→A도 같은 UID만으로 통과할 수 없다.

### 2.2 실패 뒤 버튼이 잠기는 문제

세션 조회 예외를 로그아웃으로 취급하지 않는다. 토큰 불일치와 요청 예외를 같은 계정의 복구 가능한 실패로 구분한다. 저장·조회·수정·삭제·동의 확인은 화면과 계정이 유효한 실패에만 안내를 표시하고 진행 상태를 해제한다. 입력·기록 ID·기존 재시도 요청을 그대로 유지한다.

다른 계정 또는 닫힌 화면의 결과는 계속 무시한다. 화면에 반영하는 시점에 요청 표가 유효한지도 다시 확인한다.

### 2.3 초기 인증 확인

초기 조회 전에 인증 이벤트를 구독한다. 세대가 바뀌지 않은 null→null 로그아웃 이벤트도 별도로 추적해 늦은 조회가 상태를 되돌리지 못하게 한다. 초기 조회 실패 시 확인 중 화면에 멈추지 않고 다시 확인할 수 있게 한다.

### 3.2 실행 환경과 재현

Node.js 24.19.0, Next.js 15.5.27, React 19.3.0, supabase-js 2.117.3, @supabase/ssr 0.7.0. 기존 package.json의 버전 범위로 설치한 정확한 의존성을 `package-lock.json`에 기록했다. 런타임 라이브러리를 새로 추가하지 않았다.

```bash
npm ci
npm test
npm run typecheck
NEXT_TELEMETRY_DISABLED=1 npm run build
npm run test:db
```

이번 환경에서 `npm test`의 tsx CLI가 IPC 파이프 권한 오류를 냈다. 같은 테스트를 실행하는 `node --import tsx --test tests/*.test.ts`로 검증했다. GitHub Actions에는 Node 22에서 단위·타입·빌드·임시 PostgreSQL 시험을 실행하는 검증 절차를 추가했다. Actions 결과는 실행이 완료된 뒤 확인해야 한다.

## 4. 미검증과 다음 확인

### 4.1 로컬 DB 시험

`npm run test:db`는 이번 환경에 PostgreSQL 실행 파일이 없어 실패했다. 설치 시도도 환경의 사용자 권한 전환 제약으로 실패했다. 이번 수정은 DB SQL을 바꾸지 않았지만, Claude가 보고한 이전 47개 DB 시험 결과를 이번 재실행으로 계산하지 않는다.

### 4.2 브라우저 시험

실제 두 계정 로그인·화면 전환·네트워크 지연·저장 상태 복구는 아직 미검증이다. 가상 계정의 로직 시험과 HTTP 헤더 시험을 실제 브라우저 시험으로 표현하지 않는다. 브라우저 실행 파일이 없어 로컬 화면 시험도 수행하지 못했다.

### 4.3 운영 적용 전 확인

1. GitHub Actions의 임시 DB 시험과 전체 검사 결과를 확인한다.
2. 실제 사용자 기록과 분리한 가상 계정 A/B로 미리보기에서 생성·조회·수정·삭제를 시험한다.
3. A 입력 중 B 전환, 로그아웃 뒤 A 재로그인, 늦은 응답, 같은 계정 실패·재시도에서 입력과 기록이 섞이지 않는지 확인한다.
4. 검증 결과를 사용자에게 보여준 뒤 main 병합·운영 배포 지시에 따라 진행한다.
