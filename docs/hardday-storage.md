# 힘든 날 카드 저장 방식 (404 blue 6단계)

결정: **이 기기에만 저장** (2026-11-13 사용자 합의, 개발계획서 8.1.1의 '이 기기' 선택지).

## 무엇을 어디에
- 브라우저 저장소(localStorage) 키 하나: `404blue.hardday.v1`. 서버·계정·분석 도구·로그로 보내지 않는다.
- 저장 내용: 먹을 것(최대 3개, 이름·https 주문 주소), 부탁할 사람(부르는 이름만, 최대 2명, 선택), 부탁 문장, 저장한 때.
- 전화번호·주소 같은 연락처는 받지 않는다 (제3자 정보 최소 수집, 8.2.1).

## 사용자에게 알리는 것
- 저장 버튼 옆: 이 기기 브라우저에만 저장, 다른 기기에서 안 보임, 공용 기기라면 저장하지 않는 편이 좋음.
- 보기 화면: 저장한 날짜, 공용 기기라면 지워 달라는 안내, '이 기기에서 지우기'(확인 단계를 거침, 되돌릴 수 없음).

## 안전 장치
- '저장하기'를 눌렀을 때만 저장(자동 저장 없음). 저장 후 다시 읽어 같을 때만 '저장했어요'.
- 저장소를 못 쓰는 브라우저(사생활 보호 모드 등)는 저장 버튼을 끄고 '저장하지 않고 이번에만 보기'를 준다.
- 저장값은 믿지 않고 다시 검사한다: 손상·모르는 버전이면 쓰지 않고 알림, 주소는 https만 링크로 만든다(javascript: 등 차단).
- 주문 주소는 새 창 + `rel="noopener noreferrer"`. 결제·주문 연동은 하지 않는다 (CLAUDE.md 7장).

## 재검토 반영 (2026-11-13, ChatGPT 검토)
- **다른 탭**: `storage` 이벤트로 다른 탭의 삭제·변경을 바로 반영한다. 지우면 이 탭의 보기·적던 내용도 비운다(지운 카드가 되살아나지 않게). 보기 중이면 새 내용으로 바꾸고, 적는 중이면 알리기만 한다.
- **저장 직전 확인**: 이 화면이 마지막으로 본 원본과 지금 저장소 값이 다르면 저장하지 않고 알린다. '그래도 지금 적은 내용으로 저장하기'(확인 후 저장) 또는 '저장된 카드 다시 불러오기'를 고른다.
- **읽기·저장·지우기를 따로**: 미리 써 보는 시험을 없앴다. 쓰기만 안 되는 브라우저에서도 기존 카드는 보이고, 저장 실패(용량 초과 등)는 입력·기존 카드를 그대로 둔다.
- **'저장하지 않고 이번에만 보기'는 언제나**: 유효한 입력이면 저장 가능 여부와 상관없이 쓸 수 있다.
- **적는 중 '부탁하기'는 새 탭**: 링크에 '새 탭에서 열려요'를 표시하고, 원래 탭의 초안을 유지한다.
- **주소를 자르지 않음**: 인코딩 뒤 2000자까지 통째로 저장. 넘으면 자르지 않고 저장 전에 알린다. 입력칸의 길이 제한(브라우저가 몰래 자르는 것)도 없앴다.
- **안내 문구**: "이 카드는 이 브라우저에 저장돼요. 로그아웃해도 남고, 같은 브라우저를 쓰는 사람은 로그인 없이 볼 수 있어요. 함께 쓰는 기기라면 ‘저장하지 않고 이번에만 보기’를 골라 주세요." 로그아웃 완료 문구도 "계정 기록 화면을 닫았어요. 이 브라우저에 저장한 힘든 날 카드는 남아 있어요."로 범위를 나눴다.

## 2차 재검토 반영 (2026-11-13): 확인한 버전에만 적용
- **한 번 읽기**: 처음 열 때·다시 불러올 때 저장소를 한 번 읽은 값으로 화면 카드와 비교 기준을 함께 정한다(`snapshot`). 두 번 읽는 사이 삭제돼도 어긋나지 않아, 평범한 저장으로 되살아나지 않는다.
- **지우기**: '지울까요?'를 연 순간의 카드 원본에만 적용한다. 그사이 바뀌었으면 지우지 않고 바뀐 카드를 보여 준 뒤 다시 확인받는다. 다른 탭의 변경을 받으면 확인창을 닫는다.
- **덮어쓰기**: 충돌 경고를 띄운 순간의 저장소 값에만 '그래도 저장'이 적용된다. 경고 뒤 또 바뀌면 다시 멈추고 새 버전으로 묻는다.
- **임시 카드·따로 고친 내용 지키기**: 다른 탭이 저장 카드를 지울 때, 저장 카드를 그대로 보고 있거나 고치지 않고 열어 둔 경우만 비운다. '이번에만 보기' 카드나 고친 초안은 남기고, 저장하려면 '지워진 상태'를 알린 뒤 확인을 받는다.

## 3차 재검토 반영 (2026-11-13): 탭 사이 잠금
- **Web Locks**: 이 앱의 모든 카드 저장·지우기는 같은 잠금(`404blue.hardday`)을 얻은 뒤, 잠금 안에서 원본을 다시 읽어 비교하고 쓴다. 비교와 쓰기 사이에 다른 탭이 끼어들 수 없다 (localStorage 자체에는 잠금이 없음).
- 잠금을 5초 안에 못 얻으면 쓰지 않고 "다른 창에서 저장하거나 지우는 중"이라고 알린다. 초안은 그대로.
- **잠금을 쓸 수 없는 브라우저**: 저장·지우기 버튼을 끄고 이유를 알린다. 기존 카드 보기와 '저장하지 않고 이번에만 보기'는 그대로.
- **취소**: 저장 카드를 고치다 '고치지 않고 카드로 돌아가기'를 누르면 지금 저장소를 다시 읽는다(지워졌으면 보여 주지 않음). 임시 카드를 고치다 취소할 때만 임시 보기로 돌아간다. 저장 카드가 지워진 뒤에는 돌아가기 버튼을 숨긴다.
- **초안 비교**: 다른 탭 삭제 때 '고치지 않았는지'는 정리한 값이 아니라 사용자가 입력한 값 그대로 비교한다 (`https://`만 쓴 칸도 바뀐 것으로).
- **충돌 때 지금 카드 보기**: 저장이 멈추면 지금 저장돼 있는 카드(먹을 것·사람·문장)를 초안 옆에 보여 준다. '그래도 바꾸기'는 그 보여 준 버전에만 적용된다.

## 4차 재검토 반영 (2026-11-13): 기다리는 동안의 취소
- 잠금을 기다리는 저장·지우기는 사용자가 취소하면 **잠금 요청 자체를 철회**한다(AbortSignal). 잠금을 얻는 순간에도 취소 여부를 다시 확인해, 취소한 요청은 잠금이 풀린 뒤에도 실행되지 않는다.
- 저장 대기 중에는 입력·'이번에만 보기'·돌아가기를 잠시 막고 '저장 취소'만 받는다. 취소하거나 5초가 지나면 입력 그대로 이어서 고칠 수 있다. 지우기 대기 중에는 '지우는 중…'과 '취소'를 보여 준다.
- 다른 탭이 카드를 바꾸거나 지우면, 이전 버전에 대한 충돌 미리보기·'그래도 바꾸기'를 바로 닫는다(초안은 유지). 다시 저장하면 지금 상태로 새로 확인받는다.
- 잠금을 못 쓰는 브라우저의 보기 화면: 지우기 버튼이 꺼진 이유와, 브라우저 설정에서 이 사이트의 데이터만 지우는 방법(크롬·아이폰 예시)을 안내한다.

## 5차 재검토 반영 (2026-11-13)
- 충돌 미리보기에 보여 주는 카드는 편집 시작 때의 카드와 **따로 비교**한다. 처음에 카드가 없던 탭에서도, 미리보기의 카드가 지워지거나 바뀌면 미리보기·덮어쓰기 확인만 닫고 초안은 남긴다.
- 카드 화면이 닫히면(다른 화면으로 이동) 기다리던 저장·지우기를 **철회**한다. 페이지를 완전히 떠나는 경우는 브라우저가 기다리던 잠금 요청을 함께 버린다. 도움 화면 이동은 막지 않는다.
- 키보드: 기다리기 시작하면 '저장 취소'·'취소'로 초점을 옮기고, 취소·시간 초과 뒤에는 원래 버튼으로 돌려준다.
- 사이트 데이터 삭제 안내: 지금 사이트 주소를 보여 주고 그 주소만 고르게 함. 컴퓨터 크롬 경로(Google 고객센터 문서, 영문 메뉴로 확인), 아이폰은 '설정 → 앱 → Safari → 고급 → 웹사이트 데이터'까지만 안내하고 '모든 웹사이트 데이터 제거'는 누르지 않도록 구분. 로그인 상태·사이트 설정도 지워질 수 있고 서버의 계정 기록은 지워지지 않는다고 안내. 아이폰에서 항목 하나를 지우는 실제 조작은 기기에서 확인하지 못했다.

## 6차 재검토 반영 (2026-11-13): 늦게 도착한 결과
- 저장·지우기 결과는 잠금 안에서 읽은 값이라, 화면에 반영하기 직전에 **지금 저장값을 다시 확인**한다. 그사이 다른 탭이 바꾸거나 지웠으면 늦은 결과(저장 성공 화면·지운 카드의 미리보기·빈 화면)를 그대로 보여 주지 않고 지금 상태를 보여 준다. 적던 내용은 남기고, 다시 저장하려면 지금 상태로 확인받는다.
- 복사: 클립보드 복사가 끝나기 전에 보이는 문장이 바뀌었으면 대체 복사(문장 선택 후 복사)를 하지 않고 "새 문장을 확인하고 다시 눌러 주세요"라고 안내한다.
- 초점: 저장 성공 뒤에는 카드 제목, 충돌이면 비교 안내로 옮긴다 (취소·시간 초과는 원래 버튼).

## 7차 재검토 반영 (2026-11-13)
- 결과를 반영하기 직전에 지금 저장값을 **읽지 못하면**, 저장 성공 화면·이전 미리보기·지운 카드를 보여 주지 않는다. 초안을 남기고 "지금 저장 상태를 확인하지 못했어요"라고 알린다 (지우기 뒤에도 같음).
- 복사 안내는 **가장 최근 복사 요청만** 바꾼다. 늦게 끝난 이전 요청은 무시한다.
- 초점이 있던 비교 안내가 다른 탭의 변경으로 닫히면 상태 안내로 초점을 옮긴다.

## 8차 재검토 반영 (2026-11-13)
- 안내 문구를 나눔. 저장 확인 실패: "저장됐는지 확인하지 못했어요. 적은 내용은 이 화면에 남아 있어요. 화면을 닫지 말고, 잠시 뒤 ‘이 기기에 저장하기’를 다시 눌러 주세요." ('다시 열기'는 초안이 사라질 수 있어 뺌). 지우기 확인 실패: "카드가 지워졌는지 확인하지 못했어요. 이전 카드는 화면에서 숨겼어요. 잠시 뒤 저장 상태를 다시 확인해 주세요." + 저장 버튼 대신 **'저장 상태 다시 확인'** 한 개.
- 지우기가 '실패'로 끝나도 지금 상태를 한 번 읽는다: 비어 있으면 지운 것으로, 읽을 수 없으면 이전 카드를 숨기고 다시 확인하게, 카드가 그대로면 '지우지 못했어요'.
- 클립보드 쓰기는 한 번에 하나만: 진행 중에는 버튼이 '복사 중…'으로 꺼진다. 겹친 쓰기로 붙여넣을 값과 안내가 달라지지 않는다.

## 9차 재검토 반영 (2026-11-13)
- '저장 상태 다시 확인'은 버튼 하나만 둔다('새로 적기' 없음). 저장소를 **한 번 읽은 값**으로 화면과 안내를 함께 정한다: 비었으면 지운 것으로 새 카드 입력, 지우려던 카드가 남았으면 그 카드를 보여 주고 다시 지울 수 있게, 다른 카드면 다른 창이 바꾼 것으로. 못 읽으면 버튼을 그대로 둔다. 지우기 결과 처리도 한 번 읽은 값으로.
- 저장: 쓰기는 됐는데 확인 읽기만 실패하면 '실패'가 아니라 '확인 못 함'(`unverified`, 방금 쓴 값 포함). 다음 읽기에서 방금 쓴 값과 정확히 같으면 성공으로 보여 주고, 그래도 못 읽으면 초안을 남기고 "저장됐는지 확인하지 못했어요". 이때 기준을 방금 쓴 값으로 두어, 다시 저장해도 자기 카드와 충돌하지 않는다.
- 남는 한계: 잠금은 이 코드를 쓰는 탭끼리만 맞춘다. 사용자가 브라우저 설정·개발 도구로 직접 지우는 경우는 다음 읽기에서 반영된다.

## 결정
- 로그아웃 때 이 카드를 자동으로 지우지 않는다 (검토 권고: 개인 기기에서 뜻밖에 사라질 수 있고, 로그인 없이 쓰는 기능이라 로그아웃으로 공용 기기 노출을 막을 수 없음). 대신 위 안내로 누가 볼 수 있고 언제까지 남는지 알린다.
- 연락 대상은 선택형 이름만 (검토 의견: 적절).

## 아직 하지 않은 것
- 계정 저장(다른 기기에서 보기)은 별도 동의·DB 표·RLS와 함께 나중에.
- 계획서 PDF의 '오늘 최소한'(누운 채 누르는 최소 할 일)은 이번 범위에 넣지 않았다.
- 적는 중 머리글 메뉴로 다른 화면에 가면 초안은 남지 않는다 (도움 버튼은 막지 않는다).
