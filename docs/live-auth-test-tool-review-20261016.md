# TEST 인증 갱신 시험 도구 검토 — 2026-10-16

## 범위
기준 02272d1에 /test-auth 화면과 갱신 성공 응답 보류 제어기를 추가한다. Preview + 정확한 TEST DB + 기존 인증 작업 잠금 플래그 + 기존 브라우저 전용 인증 플래그를 모두 요구한다. 운영 인증 코드·환경 변수·DB는 변경하지 않는다.

## 동작
- 공개 SDK getSession/getUser로 시작 계정을 확인하고 refreshSession()을 호출한다.
- 과거에 읽은 refresh_token을 명시적으로 전달하지 않는다. SDK가 인증 잠금 안에서 현재 세션을 선택한다. 계정이 바뀌면 원래 계정의 성공으로 표시하지 않는다.
- TEST /auth/v1/token?grant_type=refresh_token POST 성공 응답만 일시 보류한다. 요청/응답 본문은 검사·로그·파일 저장하지 않는다. 정상 SDK 세션 저장은 기존 동작이다.
- 준비 시점부터 10초 상한. 취소·화면 종료 시 보류를 풀고 fetch를 복구한다. 서버에서 이미 수행된 갱신을 취소/복구했다고 주장하지 않는다.
- 동일 실행 중 버튼을 비활성화하며 요청 중복을 ref로도 차단한다. 전달 없음/자동 해제/거절/계정 변경을 경쟁 시험 성공으로 표시하지 않는다.

## 검토에서 수정한 원인
1. 이전 토큰을 getUser 확인 전에 캡처한 뒤 SDK 잠금을 기다리면, 그사이 B가 먼저 로그인한 후 A 토큰으로 갱신해 B 세션을 덮어쓸 수 있었다. 별도 모델의 검토와 설치 SDK 가상 저장소 재현으로 확인했다. 실제 SDK 회귀 시험에서 A!=B 실패를 먼저 확인하고 명시 토큰 전달을 제거했다.
2. SDK 잠금 실패가 fetch 전에 발생하면 보류 준비가 남았다. 준비 단계 타이머와 모든 실행 종료의 미완료 준비 정리를 추가했다. 완료된 전달 증거는 비활성 cancel로 덮지 않는다.

재사용 기준: 인증 토큰을 잠금 전에 캡처해 나중에 재전달하지 않는다. 시험 도구도 운영과 같은 세션 경쟁 검토 대상이다. 취소는 서버 동작 취소와 구분한다.

## 검증 근거와 한계
- 로컬 단위 113개 및 타입 통과. 이 중 기존 잠금 꺼짐 대조 2개는 결함 재현 시험이며 보호 성공으로 세지 않는다.
- 실제 SDK·가상 저장소의 B 전환 후 큐잉 갱신은 B 자격으로 요청하고 B를 유지하며, 결과는 changed로 반환한다.
- Next 빌드·실제 HTTP 경로 gate 및 Chromium CI 결과는 PR 최신 기록으로 확정한다. 로컬 Chromium 바이너리 다운로드 실패로 로컬 브라우저 통과를 주장하지 않는다.
- 화면 시험의 SDK/백엔드가 모의인 경우 실제 서버 검증과 구분한다. 실제 메일 코드 교환과 실제 A/B 갱신 경쟁은 별도 실행 필요.
- TEST 도구는 기존 기록을 쓰거나 계정을 생성·삭제하지 않는다. 실제 Auth 거부를 만들려고 기존 A/B 세션을 폐기하지 않는다.

## 수행 방식과 판단
ChatGPT가 구현·실행 검증을 수행했고, 별도 GPT 모델이 새 문맥에서 코드 검토를 수행했다. 독립 인간 보안 감사는 아니다.
- 별도 복구 clone을 전용 작업 공간으로 사용했다. 다른 로컬 작업과 섞지 않도록 변경 파일을 제한했다.
- 기존 브라우저 전용 인증 플래그도 요구해 서버 쿠키 작성 모드에서는 도구를 숨겼다.
- 갱신 대기 중 계정 변경은 원래 계정 시험의 성공으로 세지 않는다. 비협력 서버/구버전/다른 기기까지 보호한다고 주장하지 않는다.
