# D03 첫 작업: 동의 화면 계정 보호

## 1. 범위

### 1.1 요구와 기준

PRD v3.1 F02·F04 및 D03 인증 안정화의 첫 작업이다. 기준은 main 81269d1e585b65a91a3bb07f34bfe0789021870c다. 계정 삭제와 도움 오프라인 지원은 별도 후속 작업이며 이번에 완료했다고 표시하지 않는다.

### 1.2 발견한 경로

기존 /consent는 AuthScope 밖에서 ConsentForm을 렌더했다. 동의 조회·저장은 공유 인증 클라이언트를 직접 쓰고, 완료 응답에서 계정·화면 수명 검사 없이 next로 이동했다. A의 체크 상태가 남은 화면에서 B로 바뀐 경우 B의 동의를 저장하거나, 늦은 A 조회/저장 응답이 B 화면을 이동시킬 수 있는 경로다. 실제 사용자 데이터로 재현하지 않았다.

## 2. 수정

### 2.1 화면과 요청 보호

/consent를 기존 AuthScope로 감싸 UID·generation 변경 시 체크·진행·실패 상태를 새로 만든다. getStorageConsent와 grantStorageConsent를 기존 useScopedRequest로 실행해 확인한 계정의 토큰으로 고정하고 종료/계정 변경 응답을 무시한다. 같은 계정의 인증 확인 실패는 잠금을 해제하고 체크 상태를 유지한다.

### 2.2 확인 재시도

동의 상태 확인 실패에서 새로고침 대신 다시 확인하기를 제공한다. 조회 번호 및 효과 종료 검사로 더 오래된 조회를 버린다. 저장 중에는 체크 변경/재조회와 중복 제출을 막는다. 기존 동의 문구·버전·저장 테이블·API는 유지한다.

## 3. 검증

### 3.1 로컬 실행

- 기존 단위 59개 통과.
- 타입 검사 및 Next.js 빌드 통과.
- git diff --check 통과.
- 브라우저 시험용 Playwright 패키지는 프로젝트 의존성이 아닌 임시 디렉터리에 설치했다. Chromium 다운로드가 손상돼 로컬 화면 시험을 실행하지 못했다.

### 3.2 추가한 실제 React 화면 시험

기존 CI의 실제 React 컴포넌트/가상 인증/mock backend fixture를 확장했다. 390px·1280px 각각에서 늦은 A 동의 조회, 지연 A 동의 저장 및 B 체크 초기화, 조회 실패 후 재확인, 동일 계정 세션 확인 실패·토큰 불일치·저장 실패 뒤 체크 유지/잠금 해제/재시도를 검사한다. 저장 요청의 소유 계정도 검사한다. 작성 시점 CI 실행 결과는 미확정이며 PR 설명에 해당 커밋의 결과를 기록한다.

### 3.3 데이터와 한계

분리된 실제 Supabase 두 계정 시험은 아직 실행하지 않았다. mock backend 시험을 실제 DB 로그인 E2E로 해석하지 않는다. 운영 DB·환경·권한은 조회/변경하지 않았으며 새 테이블·migration·라이브러리를 추가하지 않았다. 운영 배포는 기존 81269d1을 유지한다.

## 4. 다음 확인
