# 분리 테스트 가입 확인 콜백 변경안

상태: 검토안, 인증 동작에 미적용. 기준 기능 HEAD 7cb6408.

## 확인한 서버 쿠키 작성자
src/app/auth/callback/route.ts는 getServerClient()의 exchangeCodeForSession(code)를 호출한다. src/lib/supabase/server.ts의 setAll은 응답에 인증 쿠키를 쓴다. 현재 일반 페이지 미들웨어 제한은 /auth/*를 제외하므로 미들웨어도 이 경로의 작성자가 될 수 있다. Web Lock은 이 서버 응답을 제어하지 않는다.

## 구현할 범위
1. 승인된 TEST_BROWSER_AUTH_PREVIEW_ENABLED와 Preview·정확한 분리 DB 조건에서만 /auth/callback 및 새 /auth/complete를 서버 쿠키 갱신 없는 경로로 포함한다. 운영·다른 DB·플래그 없음은 기존 서버 코드 교환을 유지한다.
2. 테스트 /auth/callback은 서버에서 세션을 교환하지 않는다. 확인 코드를 내부 전용 /auth/complete?exchange_code=... 경로로 전달하고 no-store·Referrer-Policy: no-referrer를 설정한다. code 대신 전용 인자명을 사용해 SDK의 자동 PKCE 감지와 중복되지 않게 한다.
3. 완료 화면은 표시 전 URL에서 확인 코드를 제거하며 코드/토큰/비밀번호를 로그·스토리지·보고서에 남기지 않는다. 이동 주소는 safeNext를 거친 내부 경로만 사용한다.
4. 이미 로그인한 계정이 있으면 자동 교환하지 않는다. 현재 로그인 유지 또는 링크 확인을 계속할지 사용자 선택을 받는다. 선택 전 기존 세션을 지우지 않는다.
5. 확인을 계속하면 브라우저 클라이언트의 공개 exchangeCodeForSession을 한 번만 호출한다. React 재실행·동시 클릭·다른 탭의 계정 전환 중 오래된 콜백이 새 세션을 덮어쓰지 않도록, 코드 교환 시작의 세션 스냅샷과 교환 결과를 쿠키 저장 경로까지 연결하는 보호가 필요하다. 단순히 응답 후 화면을 숨기는 것으로 완료하지 않는다.
6. 필요한 SDK 보호 범위가 확정되지 않으면 기존 B 세션을 보존하고 코드 교환을 중단한다. 인증 성공을 합성하거나 원래 계정 코드를 새 계정 토큰으로 재시도하지 않는다.

## 확인할 시험
- 실제 Next HTTP에서 승인 조건의 callback/complete에 인증 Set-Cookie 없음과 no-store/no-referrer, 내부 경로만 이동하는지 확인.
- Chromium에서 코드 교환 단 한 번, 성공/만료/이미 사용/중단, B 로그인 중 자동 교환 미실행, 늦은 교환 응답의 B 쿠키 및 화면 보호.
- 기존 비밀번호 로그인·기록·동의·삭제·도움 화면 회귀, 운영 및 플래그 없음의 기존 동작 유지.
- 가상 코드·가상 인증 서버만 사용하는 자동 시험과 실제 가입 확인 메일 시험은 구분한다. 실제 메일 시험은 아직 미검증이며 사용자에게 확인 코드를 채팅으로 요구하지 않는다.

## 승인 범위
앞선 일반 페이지 변경 승인은 콜백을 제외했다. 이 변경은 가입 확인의 인증 방식을 바꾸므로 별도로 승인받고 적용한다. 운영 배포·운영 DB·관리자 권한 확대는 포함하지 않는다. 새 의존성 없이 가능한 범위부터 구현하며 추가 권한이나 의존성이 필요하면 먼저 설명한다.

ChatGPT가 소스 검토와 변경안 작성을 수행했다. 독립 보안 검토가 아니다.
