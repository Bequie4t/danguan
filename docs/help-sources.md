## 바꾼 이유 (2026-10-08)
- 이전 문구 "무료로 상담을 받을 수 있어요", "1577-0199로 전화하면 가까운 센터로 연결해 줘요"는 공식 출처로 일괄 보장할 수 없어 삭제·완화.
- 각 연락처 아래 출처 링크, 화면 하단에 확인 날짜 표시.

## 아직 확인할 것
- 119·112·109 보도자료 본문을 사람이 직접 열어 문구 확인.
- 도움 화면 자체의 오프라인 재방문은 지원하지 않는다. 서비스 워커·앱 캐시는 사용하지 않는다.

## 연락처 파일 저장 (2026-10-10)
- `/help/contact-card`에서 현재 `contacts.ts`의 연락처·안내·확인 날짜·출처 링크를 UTF-8 텍스트 파일로 내려받는다. 연락처를 별도 복사본으로 관리하지 않는다.
- 미리 내려받은 파일은 인터넷 없이 읽을 수 있다. 오프라인 첫 방문이나 도움 화면 자체의 오프라인 접근은 보장하지 않는다.
- 전화 연결에는 통신망, 출처 링크 열람에는 인터넷이 필요하다. 저장본에는 운영 방식 변경 가능성과 최신 도움 화면 주소를 표시한다.
- 로그인·Supabase·사용자 기록 없이 파일을 만든다. 기존 안내 내용과 확인 날짜는 그대로 유지하며, 이번 작업을 연락처 재검증으로 표시하지 않는다.
- PRD v3.1 F01/D03의 다운로드 안내 지원에 해당한다. 계정 삭제와 자동 오프라인 재방문 지원은 별도 과제다.

## 화면 디자인 변경 (2026-11-12, 404 blue 3단계)
- 배치만 바꿨다: 109를 맨 위·가장 크게, 1577-0199 다음, 119·112 나란히. 카드 전체가 전화 링크.
- 연락처 번호·안내 문구·출처·확인 날짜(2026-10-08)는 `contacts.ts` 그대로다. 이번 작업은 연락처 재검증이 아니다.
- 출처는 각 카드 아래 대신 화면 아래 '확인한 곳'에 연락처별로 모아 보여 준다.
- 디자인 시안의 '가까운 센터 찾기' 링크는 넣지 않았다 (병원·센터 검색은 별도 지시 전까지 하지 않음).
- 도움 화면은 여전히 로그인·기록 저장·Supabase 코드를 가져오지 않는다: `tests/help-independence.test.ts`가 import를 끝까지 따라가 확인한다.
- 공통 머리글에서 인증 분리 (2026-11-13): 도움 화면(`/help`, `/help/…`)에서는 계정 메뉴가 로그인 코드를 불러오지도 초기화하지도 않는다. 계정 메뉴는 로그인 코드를 필요할 때만(`import()`) 불러오고, 오류가 나도 그 부품만 숨긴다(`QuietBoundary`). 설정 주소 형식이 잘못되면 브라우저 클라이언트는 오류 대신 '설정 없음'으로 다룬다. 머리글 링크는 `next/link` 대신 일반 링크로 바꿔, 도움 화면이 홈·로그인 코드 묶음을 내려받지 않게 했다. `scripts/browser/help-real.sh`가 설정 없음·주소 형식 오류·닿지 않는 주소로 각각 실제 앱을 빌드해 확인한다.
- 기록 저장 중·저장 실패 화면에서도 도움 버튼은 바로 이동 (2026-11-13): 기록 화면은 저장 중·실패 때 창을 떠나기 전에 묻는다(`beforeunload`). 머리글 도움 버튼이 일반 링크가 되면서 이 확인창이 도움 버튼에도 떠, '취소'를 누르면 도움 화면으로 못 가는 문제가 있었다(ChatGPT 검토로 발견, 로컬 실제 로그인으로 재현). 도움 버튼에 `data-leave-ok` 속성만 달고, 기록 화면의 확인 장치(`src/lib/leave-guard.ts`)가 그 링크를 그냥 누른 직후에는 묻지 않게 했다. 다른 메뉴·창 닫기는 계속 묻는다. 도움 화면은 이 장치 코드를 불러오지 않는다.
