# PR #7 실제 로그인·실제 DB 구조 시험 — 2026-11-12

## 왜 로컬에서 했나
- 분리 테스트 DB(`wxqmqksqjmfflzghozuq`)가 결제 문제로 일시 정지되어 미리보기에서 시험할 수 없었다.
- 대신 작업 환경에 **임시 Supabase 전체(인증 서버·DB·API)**를 띄우고, 이 저장소의 마이그레이션 2개를 그대로 적용한 뒤 PR #7 코드(976ea5b)를 `next build`·`next start`로 실행했다.
- 운영 DB·테스트 DB·실제 계정은 쓰지 않았다. 계정은 시험 때마다 새로 만든 가상 주소(`local-*@example.test`), 데이터는 가상 값만.
- 실행: `bash scripts/local-e2e/run.sh` (Docker, `npx supabase@2`, Playwright 필요. package.json 변경 없음).

## 방법
- 실제 Chromium 화면을 눌러 진행. 응답 유실은 Playwright가 요청을 서버에 보낸 뒤 응답만 끊어서 만들었고, '늦게 도착'은 요청을 서버에 닿지 않게 끊은 뒤 같은 요청을 나중에 보냈다.
- '다른 탭/기기'는 같은 계정으로 따로 로그인한 supabase-js 클라이언트가 실제 RPC(`update_checkin`·`delete_checkin`·`create_checkin`)를 호출했다.
- DB 상태는 psql로 직접 조회했다.
